# HyperbolicDeltaNet model dispatch and streaming cache

Set `HyperbolicDeltaNetConfig(tensor_core=True, attn_mode='chunk')` to select the unprotected Tensor Core path during training and chunk prefill. The flag is serialized in model configuration and forwarded to each layer. Short evaluation sequences retain the recurrent route, and unsupported TC key dimensions retain the existing chunk fallback. The protected operator is a distinct route, not a TC implementation.

Protected cached calls preserve globally aligned `chunk_size` boundaries. The cache retains the public normalized state and bank fields, plus `pending` input tensors and `block_start` for an unfinished chunk. The partial prefix is replayed from that fixed starting bank; a completed chunk advances the bank. At most `chunk_size-1` tokens are retained and replayed. Empty input calls preserve the state. Cache tensor transforms retain batch dimension zero, including pending data.

Protected convolution uses the stateful prefill calculation for single-token calls as well, avoiding the different rounding path of the dedicated update kernel. Floating-point equality is tested within declared tolerances, not asserted bitwise. CPU reference tests use float64 without short convolution; GPU tests cover FP32 with and without convolution, full, token-wise, irregular and empty segments for chunk sizes16/32. Existing legacy cache dictionaries without partial-block metadata must represent a chunk boundary; re-prefill an old partial prefix when migrating an in-flight cache.

`protected_checkpoint=True` preserves the operator-level checkpoint default. When a full model already uses non-reentrant layer checkpointing, `protected_checkpoint=False` can avoid nested recomputation. This is an explicit memory/performance trade-off, not an automatic default change. The regression compares both loss and every parameter gradient between the two policies with layer checkpointing enabled.

The GSA2 companion script `scripts/benchmark_hyperbolic_16k.py` compares full24-layer models (hidden2048, heads16, head128, V128, intermediate5184, vocabulary32000) using B8/T2048, B4/T4096, B2/T8192 and B1/T16384. It times forward/loss/backward/AdamW, excludes input generation, zero_grad and result-file I/O, and records per-step seconds plus allocated/reserved VRAM. All variants use BF16 autocast, FP32 parameters, fixed seed, full non-reentrant layer checkpointing and TC_FAST=0. GDN and HDN parameter counts are recorded rather than claimed identical. This is single-GPU throughput per configuration; multiple GPUs run distinct configurations, not one DDP throughput number.

`--no-inner-checkpoint` selects the protected optimized policy. The initial comparison uses2 warmups and5 measured steps. Preserve raw samples, report variability, and extend warmups/repetitions before interpreting small latency differences. No long-training quality or GDN-parity claim follows from these measurements.
