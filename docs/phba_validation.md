This record validates expanded coverage of supported PHBA model behavior on NVIDIA H20, PyTorch 2.9.0+cu128, Triton 3.5.0, Transformers 5.6.2 and FlashAttention 2.8.3.post1. The source/runtime manifest has SHA256 `7565c76ee8a6c67c8186d056478749e54e9ce29fb56fe1c48a549775074c1f04`, computed from `json.dumps(path_to_sha256, sort_keys=True).encode()` using repository-relative paths. ## Correctness and API coverage

The strict source gate passes **101 tests, no skips**: 22 operator, 25 projection, 37 model and 17 benchmark cases. `FLA_CI_ENV=0 PHBA_REQUIRE_EXACT_GEMM=1` makes numerical failures and an unavailable pinned H20 backend fail the gate. Seven additional PHBA cases selected from the shared configuration and Transformers suites pass, with no skips (550 other cases deselected). Sixteen CPU-compatible PHBA cases also pass with CUDA hidden (21 accelerator cases deselected). GPU-suite warnings include the TF32 API deprecation and advertised fused-linear-CE precision notices; the standalone installed suite also reports unregistered smoke markers. The CPU run reports the expected CPU-platform notice. All numerical assertions remain strict.

Projection coverage checks all three screened GEMM geometries against native outputs and gradient bytes. It includes FP32 autocast inputs, BF16 views aligned to 16 bytes, unaligned activations and incoming gradients, and separate unaligned A/B GEMM operands. Tests assert actual cuBLASLt execution for eligible calls and zero calls for the alignment fallback. Fused SwiGLU materializes a fresh aligned activation; unaligned pre-activation inputs therefore remain eligible when the actual GEMM operands are aligned. Its unaligned-gradient path retains the original einsum operation.

The retained reference-consolidation audit at `5bb4e02c`, against baseline `5e71a2cb6ad14fb2147e48ecb26349f417139b7d`, covers nine combinations of FP16/BF16 dense/packed/no-history inputs and training, inference or forced low-workspace execution. Outputs, final states and all supported gradients are byte-identical to the baseline. Instrumentation confirms that the retained integer metadata kernels, sparse dK/dV kernel, query-owner dQ and sequential prefix backward really execute.

Operator/model coverage includes FP16/BF16 dense and packed outputs and all six input gradients, final states, independent routing/metadata references, FP64 formula gradcheck, save/load, central exports, checkpoint gradients, padding, cache-free generation, affine-free norms, invalid head dimensions and conflicting sequence plans. Forced low-workspace prefix/tape fallbacks are checked against their references and repeat deterministically. Existing tolerances are unchanged. In that preceding consolidation, all 21 moved reference function/class definitions retained identical ASTs. Its six before/after reference modes cover the FP64 mathematical function and public wrapper, plus FP16/BF16 storage-aware references with PyTorch or FlashAttention local branches; returned tensors and all six input gradients match byte-for-byte. All 33 production Triton JIT functions and screened GEMM descriptors are unchanged. That prior reference move changed only the routing oracle's lazy import outside the consolidated reference module; the current test expansion changes no production module.

In the preceding `5e71a2cb` complete-step study, every pair matches all 267 initial parameter tensors, inputs, loss, gradient norm, raw/clipped gradient bytes and optimizer-state hashes after 70 steps. The installed split wheels also pass the 1.264B benchmark-model gate with all three exact GEMM sessions active: loss `10.784871101379395`, gradient norm `2.495190382003784`, and no raw or clipped gradient mismatches.

## Model test scope

PHBA has 37 dedicated model cases, alongside 22 operator, 25 projection and two PHBA registry cases. Fifteen existing shared benchmark cases complete the 101-case source gate. Seven shared configuration/Transformers PHBA cases and a 16-case CPU subset are also executed separately. The GPU equivalence, fusion and interface tests execute real two-layer PHBA models.

| Area                                | Current PHBA coverage                                                                                                                                                                                                 | Boundary                                                                               |
| ---                                 | ---                                                                                                                                                                                                                   | ---                                                                                    |
| Dense/packed equivalence            | Batched dense BF16, ragged BF16 and left-padded FP16 with a one-token sequence; all hidden states, logits, loss and every parameter gradient compared                                                                 | Labels explicitly mask padding and sequence starts before shifted LM loss              |
| Padding and generation              | Right/left padding in BF16 and left padding in FP16 against independent sequences; cache-free greedy generation, including a left-padded batch crossing a chunk boundary                                              | Persistent cache decoding remains unsupported                                          |
| Loss contracts                      | Mean/sum, label smoothing, ignore indices, custom criteria, integer/tensor item counts, unchanged input labels and an independent L2Warp gradient oracle                                                              | Lightweight CPU contract cases use a zero-layer model                                  |
| Loss/fusion combinations            | Native CE, fused CE and fused-linear CE; all four norm/SwiGLU fusion settings in five representative cases; L2Warp, packed inputs and tied weights included                                                           | Representative combinations, not a full Cartesian product                              |
| Forward/decoder interfaces          | Token IDs/embeddings, positional/keyword calls, training/eval, tuple/dict returns, hidden states, no-cache outputs, logits slicing/index selection and legacy selection alias; head/loss and all gradients checked    | Supported cache-free contract only                                                     |
| Initialization                      | Native/fused and affine-free norms, QKV biases, tied weights, pad embeddings, rotary frequencies, meta-to-CPU materialization, NaN-poisoned reinitialization, residual rescale/zero strategies and parameter identity | Ordinary tensors; DTensor initialization remains unvalidated                           |

Native loss-interface comparisons preserve PyTorch's autocast input precision. Fused-loss comparisons use an explicit FP32 cross-entropy reference, matching their accumulation contract. Loss comparisons use the existing 1e-3 bound and full-model AMP gradient comparisons use 0.006; no existing tolerance was relaxed. The L2Warp CPU oracle differentiates the independently expressed max-logit penalty. Meta initialization runs in a subprocess so the shared operator-test NaN-allocation wrappers cannot pollute Torch's cached device-factory set.

Only `tests/models/test_modeling_phba.py` is changed among Python files. Other models' tests and production modules are untouched. PHBA remains outside the hand-written shared forward/decoder/initialization lists; its dedicated tests now cover the supported equivalent contracts directly. The scripts remain `tests/models/test_modeling_phba.py`, `tests/ops/test_phba.py`, `tests/layers/test_phba_linear.py` and `tests/benchmarks/test_phba_registry.py`.

## Reproduction and scope

See [the PHBA guide](phba.md) for installation, supported APIs, execution paths and benchmark commands. Exact paired reproduction additionally requires the recorded native normalization launch choices and reference hashes; raw experiment artifacts remain outside the source tree. Shared Python edits in the full PR remain limited to central exports, benchmark registration, the split-package builder and its contract test. Other model implementations are unchanged.

Default PHBA parameter names and training mathematics are preserved. Invalid sequence plans are rejected; `elementwise_affine=False` omits normalization scale parameters. Persistent decode caching, context/tensor parallelism, full-graph compilation, other accelerators and convergence remain outside validation. Optimizer selection remains the training framework's responsibility.
